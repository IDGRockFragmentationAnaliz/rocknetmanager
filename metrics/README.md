# Panoptic Quality

```python
from rocknetmanager.metrics import panoptic_quality

pq = panoptic_quality(pred=prediction, gt=ground_truth)
```

Входы — двумерные бинарные скелеты `np.uint8` одинакового размера:
`0` — фон, `1` или `255` — граница. Функция возвращает `float` от 0 до 1
и не изменяет входы.

Объекты — замкнутые 4-связные области внутри 8-связных границ.
Сами линии и области, достигающие края изображения, исключаются.
Пары объектов сопоставляются при `IoU > 0.5`:
`PQ = sum(IoU) / (TP + 0.5 * FP + 0.5 * FN)`.
Все объекты относятся к одному классу. Если объектов нет на обеих картах,
результат равен `1.0`; если только на одной — `0.0`.
Определение метрики: [Panoptic Segmentation, CVPR 2019](https://openaccess.thecvf.com/content_CVPR_2019/html/Kirillov_Panoptic_Segmentation_CVPR_2019_paper.html).

Перед PQ исключённые маской пиксели нужно закрасить белым на обеих картах:

```python
prediction = prediction.copy()
ground_truth = ground_truth.copy()
prediction[image_mask == 0] = 255
ground_truth[image_mask == 0] = 255
pq = panoptic_quality(prediction, ground_truth)
```

В проекте это выполняется при запуске
`python -m scripts_pipeline.task4_validate_pq` из корня проекта.
Настройки модели и данных берутся из `scripts_pipeline/task4_validate.py`.
Выводится PQ каждого изображения и среднее по изображениям.

# Boundary F-score

`boundary_f_score` сравнивает две однопиксельные карты линий с допустимым отклонением в несколько пикселей.

```python
from rocknetmanager.metrics import boundary_f_score

f1 = boundary_f_score(
    edges_pred=prediction,
    edges_gt=ground_truth,
    tolerance_px=3,
)
```

Обе карты должны иметь одинаковый размер, тип `np.uint8` и значения:

- `255` — линия;
- `0` — фон.

## Как считается

При `tolerance_px > 0` линии GT и prediction расширяются эллиптическим ядром размером:

```text
2 × tolerance_px + 1
```

После этого вычисляются:

```text
precision = число prediction-пикселей рядом с GT
            ------------------------------------
            общее число prediction-пикселей

recall    = число GT-пикселей рядом с prediction
            ------------------------------------
            общее число GT-пикселей

F1        = 2 × precision × recall
            ----------------------
              precision + recall
```

## Почему расширяются разные карты

Расширение используется только как зона поиска ближайшей линии. Оно не добавляет новые пиксели в знаменатель метрики.

### Precision: расширяется GT

Для каждого исходного пикселя prediction задаётся вопрос: **есть ли рядом с ним линия GT?**

```text
совпавшие prediction-пиксели = prediction ∩ расширенный GT

precision = совпавшие prediction-пиксели
            ----------------------------
            все prediction-пиксели
```

Поэтому расширяется именно GT: он образует допустимую область, в которую должна попасть предсказанная линия. Сам prediction не расширяется и в знаменателе учитывается в исходном виде.

Низкий precision означает, что prediction содержит много лишних линий, рядом с которыми нет GT.

### Recall: расширяется prediction

Для каждого исходного пикселя GT задаётся обратный вопрос: **есть ли рядом с ним предсказанная линия?**

```text
совпавшие GT-пиксели = GT ∩ расширенный prediction

recall = совпавшие GT-пиксели
         --------------------
         все GT-пиксели
```

Здесь расширяется prediction: он образует допустимую область вокруг найденных линий. GT остаётся исходным, потому что recall измеряет, какая доля настоящей разметки была покрыта предсказанием.

Низкий recall означает, что значительная часть линий GT не была найдена.

Расширять одну и ту же карту для обеих метрик неправильно: тогда одна из проверок перестанет отвечать своему вопросу. Precision направлен от prediction к GT, а recall — от GT к prediction. F1 объединяет эти два направления.

Например, если prediction точно совпадает только с короткой частью длинной линии GT, precision будет высоким, а recall — низким. Если prediction покрывает GT, но дополнительно содержит много посторонних линий, recall будет высоким, а precision — низким.

Например, при `tolerance_px=3` предсказанная линия считается совпавшей, если она проходит не дальше примерно трёх пикселей от GT.

При `tolerance_px=0` учитываются только точные попиксельные совпадения.

## Особые случаи

- если обе карты пустые, результат равен `1.0`;
- если линия присутствует только на одной карте, результат равен `0.0`;
- результат находится в диапазоне от `0.0` до `1.0`.

Метрика оценивает близость пикселей линий, но не проверяет их связность, количество разрывов или правильность отдельных полилиний.
